# Lostar Electric — sito statico

Il sito comprende la home, tre pagine per i servizi industriali, House Core, contatti, articoli e pagine legali. I vecchi hash dei servizi reindirizzano alle pagine corrispondenti. Ogni pagina ha titolo e metadati propri.

Dalla radice del repository: `python3 -m http.server 4181 --bind 127.0.0.1 --directory site`. Il server Python richiede gli URL con estensione `.html`; gli URL puliti sono gestiti da Vercel tramite `vercel.json`.

Il tema attivo usa `modern-theme.css` sopra i fogli esistenti, Archivo locale e il logo inverso nell'intestazione navy. L'immagine industriale della home è generata a scopo illustrativo, non documenta una realizzazione Lostar ed è dichiarata come tale nella pagina. Prompt e provenienza sono registrati in `docs/lostar-hero-image-prompt.txt` e `assets/industrial/lostar-hero-industrial.provenance.json`.

La selezione del servizio nei contatti usa `?servizio=quadri|automazione|collaudo|house-hardware|house-installazione`. Il modulo aggiorna i documenti suggeriti; il comune diventa obbligatorio per l’installazione House Core. I moduli Contatti e House Core chiedono a `GET /api/contact` se l'invio è disponibile. Quando lo è, `POST /api/contact` riceve solo i campi testuali e la funzione Vercel inoltra la richiesta via Resend; gli allegati non sono caricati. Il materiale tecnico, incluso lo ZIP dei layer House Core, viene richiesto dopo il primo contatto. La copia locale del testo resta disponibile anche se l'invio non è configurato, con fallback selezionabile se il browser nega l’accesso agli appunti.

L'invio usa BotID Basic di Vercel. `botid-client.js` viene inizializzato prima degli script dei due moduli e protegge esclusivamente `POST /api/contact`; la Function verifica ogni richiesta valida con `checkBotId({ advancedOptions: { checkLevel: 'basic' } })` prima di chiamare Resend. I proxy e le intestazioni per la challenge sono in `vercel.json`. Se la libreria client non parte o la verifica fallisce, il pulsante di invio viene nascosto e resta la copia locale del testo. `GET /api/contact` non richiede BotID. Per rigenerare il bundle browser versionato: `cd site && npm ci && npm run build:botid`; la radice Vercel resta questa cartella e non richiede un build automatico. Per i test: `cd site && npm test`.

BotID in produzione richiede che **Secure backend access with OIDC federation** sia attivo nelle impostazioni Security del progetto Vercel; il token viene fornito automaticamente alla Function e non va copiato nel repository. La verifica locale di BotID usa un bypass di sviluppo, quindi dopo il deploy occorre provare il modulo nel browser sul dominio del sito e verificare che una richiesta automatica senza challenge sia rifiutata. Non attivare Deep Analysis: la route impone Basic sia sul client sia sul server. La [documentazione Vercel](https://vercel.com/docs/botid/get-started) descrive il flusso e la [configurazione avanzata](https://vercel.com/docs/botid/advanced-configuration) conferma che i livelli devono coincidere.

L'indirizzo destinatario non deve comparire in file pubblici, HTML, JavaScript del browser o documentazione. Configurare esclusivamente nelle variabili d'ambiente server del progetto Vercel `CONTACT_RECIPIENT` (destinatario riservato), `CONTACT_SENDER` (mittente autorizzato su un dominio verificato in Resend) e `RESEND_API_KEY` (chiave privata). Impostarle negli ambienti Vercel in cui il modulo deve funzionare, senza aggiungerne i valori al repository. Se manca una variabile, `GET /api/contact` restituisce solo `{ "available": false }`, il pulsante di invio resta nascosto e i visitatori possono copiare il testo; nessun invio avviene. Il server Python locale serve le pagine statiche ma non esegue `/api/contact`, quindi mostra sempre questo stato di fallback. Senza JavaScript la navigazione e i download restano disponibili; i moduli sono disabilitati con una spiegazione.

I pacchetti Mac e Windows del 22 settembre includono l’export PDF e la selezione dei livelli. I download precedenti sono conservati per i link condivisi. Le tavole dimostrative usano dati sintetici; generazione e verifiche in `tools/generate-house-demo.mts` e `assets/house-demo/verification.json`. I tre schemi industriali sono generati da `tools/generate-industrial-diagrams.mjs`, senza caratteristiche di prodotti reali.

Vercel: progetto esistente `lostar-electric`, radice di deploy questa cartella; nessun framework/build. Eseguire il deploy dalla radice del repository collegato, perché Vercel ha già `site` come Root Directory. L’accesso CLI è funzionante e il sito è pubblicato su `lostartechnology.com`; `lostar-electric.vercel.app` reindirizza al dominio definitivo. Audit e verifiche sono nella cartella `docs/` del repository.

Il dominio definitivo è `lostartechnology.com`, registrato su Squarespace e collegato a Vercel. Le pagine hanno canonical e `og:url` sul dominio definitivo; `sitemap.xml` elenca gli URL pubblici e `robots.txt` indica la sitemap. `www` reindirizza al dominio senza prefisso. Configurazione e record DNS sono documentati in `docs/domain-migration-2026-09-23.md`.
